Prototype · Spring 2026

Toxicity Guard: when should an AI answer, ask, or refuse?

Always answering is helpful but unsafe. Always refusing is safe but useless. A fixed cut-off misses the borderline cases. Toxicity Guard teaches a small reinforcement-learning agent to make the call step by step, around a language model that stays unchanged.

  1. Read the prompt

    A toxicity classifier scores the request as low, medium, or high risk.

  2. First decision

    From the prompt alone, the agent either drafts a reply, asks a second safety model to check an unclear prompt, or refuses straight away.

  3. Score the draft

    If a draft is written, the classifier scores the draft itself, because a safe-looking prompt can still produce a harmful reply.

  4. Second decision

    Having seen the draft, the agent either sends it or blocks it.

Beat all 4 fixed rules
e.g. always answer, always refuse, hard threshold. Highest return on a 5,000-prompt held-out set, across 10 seeds (permutation test p < 0.0001)
Matches the optimum
its first decision equals the exact optimal policy, checked by dynamic programming, on 10 of 10 seeds
Fully inspectable
the whole policy is a 51-entry table that can be read state by state, with no black box

Built with a RoBERTa toxicity classifier, Llama-3.2-3B for drafts, Qwen3Guard-Gen-8B as the second judge, and 15,000 prompts from RealToxicityPrompts. Doctoral coursework project, United Arab Emirates University.

LimitsThis is a simulation study. Safety labels come from classifiers, not human judges, so any bias in those judges can carry into the policy. It is not a deployed safety system.
